# 模型切换机制

## 核心思路

把模型的所有连接信息折叠成一个 **id 字符串**，工厂负责把 id 展开成完整的模型实例。

```
前端下拉框选 → modelId = "ollama-qwen3-vl"
     │
     ▼ POST /api/chat {message, model}
     │
     ▼ Controller 取出 modelId
     │
     ▼ ChatModelFactory.getOrCreate(modelId)
     │    ├─ 1. 按 id 查 ModelDefinition (yml 里的配置)
     │    └─ 2. cache.computeIfAbsent → OpenAiApi + OpenAiChatModel.builder()
     │
     ▼ model.call(message)
```

## 4 个文件分工

| 文件 | 角色 | 干的事 |
|---|---|---|
| `application.yml` | 菜单 | 3 条模型配置（id/baseUrl/apiKey/modelName）+ exclude Spring AI 自动配置 |
| `ChatConfig` | 抄写员 | `@ConfigurationProperties` 把 yml 自动绑定成 `List<ModelDefinition>` |
| `ChatModelFactory` | 领班 | 按 id 翻配置卡 → 创建 `OpenAiChatModel` → ConcurrentHashMap 缓存 |
| `ChatController` | 服务员 | 从请求 body 取 modelId → 传给工厂 → `model.call()` 一行搞定 |

## Step 1：yml 里写配置 + 关掉自动配置

```yaml
spring:
  # 重要: 关掉 Spring AI 自带的自动配置 —— 我们手动 @Bean 创建模型实例
  autoconfigure:
    exclude:
      - org.springframework.ai.model.openai.autoconfigure.OpenAiChatAutoConfiguration
      - org.springframework.ai.model.openai.autoconfigure.OpenAiAudioSpeechAutoConfiguration
      - org.springframework.ai.model.ollama.autoconfigure.OllamaChatAutoConfiguration
      # ... 其他不需要的 AI 自动配置

chat:
  models:
    - id: remote-deepseek
      name: "DeepSeek Flash (远程)"
      base-url: https://api.deepseek.com      # 注意: 不带 /v1, Spring AI 自动拼
      api-key: ${DEEPSEEK_API_KEY:}
      model-name: deepseek-flash
      temperature: 0.7
```

**两个关键点**：
- `base-url` **不带** `/v1` —— Spring AI 的 `OpenAiApi` 内部会自动拼 `/v1/chat/completions`
- `spring.autoconfigure.exclude` —— 关掉自动配置，否则启动时它会抢跑创建 Bean 导致报错

每个模型 = 一组 **三元组**：`baseUrl` + `apiKey` + `modelName`。

## Step 2：ChatConfig 自动绑定

```java
@Configuration
public class ChatConfig {

    @Bean
    @ConfigurationProperties(prefix = "chat")
    public ChatProperties chatProperties() { return new ChatProperties(); }

    @Bean
    public List<ModelDefinition> modelDefinitions(ChatProperties props) {
        return props.getModels() != null ? props.getModels() : new ArrayList<>();
    }

    public static class ChatProperties {
        private List<ModelDefinition> models;
        // getter/setter
    }
}
```

`@ConfigurationProperties` 自动把 yml 的 `chat.models` 数组绑定成 `List<ModelDefinition>`。

## Step 3：工厂按 id 找 + 缓存

```java
@Component
public class ChatModelFactory {

    private final List<ModelDefinition> definitions;
    private final Map<String, ChatModel> cache = new ConcurrentHashMap<>();

    public ChatModelFactory(List<ModelDefinition> definitions) {
        this.definitions = definitions;
    }

    public ChatModel getOrCreate(String modelId) {
        // 1. 按 id 找配置卡
        ModelDefinition def = definitions.stream()
                .filter(m -> m.getId().equals(modelId))
                .findFirst()
                .orElseThrow(() -> new IllegalArgumentException("未知模型: " + modelId));

        // 2. computeIfAbsent —— 第一次才创建, 后续直接命中
        return cache.computeIfAbsent(modelId, id -> {
            String apiKey = def.getApiKey().isBlank() ? "ollama" : def.getApiKey();

            // OpenAiApi 负责 HTTP 连接
            OpenAiApi openAiApi = OpenAiApi.builder()
                    .baseUrl(def.getBaseUrl())       // 不带 /v1!
                    .apiKey(apiKey)
                    .build();

            // OpenAiChatOptions 负责模型参数
            OpenAiChatOptions options = OpenAiChatOptions.builder()
                    .model(def.getModelName())
                    .temperature(def.getTemperature())
                    .build();

            // OpenAiChatModel 把 API + Options 组装成可用的 ChatModel
            return OpenAiChatModel.builder()
                    .openAiApi(openAiApi)
                    .defaultOptions(options)
                    .build();
        });
    }
}
```

**Spring AI 的三层结构**：
- `OpenAiApi` —— HTTP 连接层（baseUrl + apiKey）
- `OpenAiChatOptions` —— 模型参数层（model + temperature）
- `OpenAiChatModel` —— 业务层（实现 `ChatModel` 接口）

**三个关键点**：
- `ConcurrentHashMap` —— 线程安全，多请求不会重复创建
- `computeIfAbsent` —— 第一次请求才建实例
- `apiKey` 空则用 `"ollama"` —— Ollama 不校验 key，但 Spring AI 要求非空，用 dummy 值绕过

## Step 4：Controller 取 id 调工厂

```java
@PostMapping("/chat")
public Map<String, String> chat(@RequestBody Map<String, String> body) {
    String modelId = body.getOrDefault("model", "remote-deepseek");
    ChatModel model = factory.getOrCreate(modelId);

    // Spring AI ChatModel.call(String) —— 一行搞定!
    String reply = model.call(body.get("message"));
    return Map.of("reply", reply == null ? "" : reply);
}
```

**和 LangChain4j 对比**：
```java
// LangChain4j: 要 3 行
ChatRequest req = ChatRequest.builder().messages(UserMessage.from(text)).build();
String reply = model.chat(req).aiMessage().text();

// Spring AI: 1 行
String reply = model.call(text);
```

## 为什么 Ollama 和 DeepSeek 都能用 OpenAiChatModel？

因为 Ollama 提供了 OpenAI 兼容端点 `/v1/chat/completions`，DeepSeek 本身就是 OpenAI API 兼容的。Spring AI 只认协议不认后端：

```
OpenAiApi(baseUrl="https://api.deepseek.com")
    → 内部拼 /v1/chat/completions → POST https://api.deepseek.com/v1/chat/completions

OpenAiApi(baseUrl="http://localhost:11434")
    → 内部拼 /v1/chat/completions → POST http://localhost:11434/v1/chat/completions
```

同一个类，不同 baseUrl → 打到完全不同的服务。

## 踩坑记录

**坑 1：base-url 要不要带 `/v1`？**

Spring AI 的 `OpenAiApi` 内部会自动拼 `/v1/chat/completions`。所以：
- ✅ 写 `https://api.deepseek.com`
- ❌ 不要写 `https://api.deepseek.com/v1`（会变成 `/v1/v1/chat/completions` → 404）

LangChain4j 时代我们要写完整 URL，这个迁移时最容易忘。

**坑 2：Spring AI 自动配置抢跑**

启动报 `OpenAI API key must be set` 错误 → 它要自动创建 OpenAiChatModel Bean。解法：`spring.autoconfigure.exclude` 掉所有 AI 自动配置类，我们手动在工厂里建。

**坑 3：exclude 的完整类名**

要用实际的类名，不是通配符。1.0.3 版本需要 exclude 这几个：
- `OpenAiChatAutoConfiguration`
- `OpenAiAudioSpeechAutoConfiguration`
- `OpenAiAudioTranscriptionAutoConfiguration`
- `OpenAiEmbeddingAutoConfiguration`
- `OpenAiImageAutoConfiguration`
- `OpenAiModerationAutoConfiguration`
- `OllamaChatAutoConfiguration`
- `OllamaEmbeddingAutoConfiguration`
