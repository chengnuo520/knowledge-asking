# 模型切换机制

## 核心思路

把模型的所有连接信息折叠成一个 **id 字符串**，工厂负责把 id 展开成完整的模型实例。

```
前端下拉框选 → modelId = "ollama-qwen3-vl"
     │
     ▼ POST /api/chat {message, model}
     │
     ▼ Controller 取出 modelId
     │
     ▼ ChatModelFactory.getOrCreate(modelId)
     │    ├─ 1. 按 id 查 ModelDefinition (yml 里的配置)
     │    └─ 2. cache.computeIfAbsent → OpenAIChatModel.builder()
     │
     ▼ ReActAgent.builder().name("assistant").model(model).build()
     ▼ agent.call(Msg).block().getTextContent()
```

## 4 个文件分工

| 文件 | 角色 | 干的事 |
|---|---|---|
| `application.yml` | 菜单 | 3 条模型配置（id/baseUrl/apiKey/modelName），无需 exclude 自动配置 |
| `ChatConfig` | 抄写员 | `@ConfigurationProperties` 把 yml 自动绑定成 `List<ModelDefinition>` |
| `ChatModelFactory` | 领班 | 按 id 翻配置卡 → `OpenAIChatModel.builder()` → ConcurrentHashMap 缓存 |
| `ChatController` | 服务员 | 从请求 body 取 modelId → 工厂拿模型 → `Msg` 交给 `ReActAgent` 调用 |

## Step 1：yml 里写模型配置

```yaml
chat:
  models:
    - id: remote-deepseek
      name: "DeepSeek Flash (远程)"
      base-url: https://api.deepseek.com/v1   # OpenAI 兼容端点, 按供应商文档填写
      api-key: ${DEEPSEEK_API_KEY:}
      model-name: deepseek-flash
      temperature: 0.7
```

**两个关键点**：
- `chat.models` 是我们自己的配置，AgentScope 不会自动读取——工厂按 id 取出后交给 `OpenAIChatModel.builder()` 显式创建
- `base-url` 要写完整的 OpenAI 兼容端点（通常带 `/v1`），AgentScope 只会在其后请求 `/chat/completions`，不会替你补 `/v1`

每个模型 = 一组 **三元组**：`baseUrl` + `apiKey` + `modelName`。

## Step 2：ChatConfig 自动绑定

```java
@Configuration
public class ChatConfig {

    @Bean
    @ConfigurationProperties(prefix = "chat")
    public ChatProperties chatProperties() { return new ChatProperties(); }

    @Bean
    public List<ModelDefinition> modelDefinitions(ChatProperties props) {
        return props.getModels() != null ? props.getModels() : new ArrayList<>();
    }

    public static class ChatProperties {
        private List<ModelDefinition> models;
        // getter/setter
    }
}
```

`@ConfigurationProperties` 自动把 yml 的 `chat.models` 数组绑定成 `List<ModelDefinition>`。

## Step 3：工厂按 id 找 + 缓存

```java
@Component
public class ChatModelFactory {

    private final List<ModelDefinition> definitions;
    private final Map<String, OpenAIChatModel> cache = new ConcurrentHashMap<>();

    public ChatModelFactory(List<ModelDefinition> definitions) {
        this.definitions = definitions;
    }

    public OpenAIChatModel getOrCreate(String modelId) {
        // 1. 按 id 找配置卡
        ModelDefinition def = definitions.stream()
                .filter(m -> m.getId().equals(modelId))
                .findFirst()
                .orElseThrow(() -> new IllegalArgumentException("未知模型: " + modelId));

        // 2. computeIfAbsent —— 第一次才创建, 后续直接命中
        return cache.computeIfAbsent(modelId, id -> {
            String apiKey = def.getApiKey().isBlank() ? "ollama" : def.getApiKey();

            // OpenAIChatModel 一个 builder 同时收下连接信息与模型参数
            return OpenAIChatModel.builder()
                    .apiKey(apiKey)
                    .baseUrl(def.getBaseUrl())       // 完整 OpenAI 兼容端点
                    .modelName(def.getModelName())
                    .stream(false)
                    .build();
        });
    }
}
```

**AgentScope 的两层结构**：
- `OpenAIChatModel` —— 连接与模型参数（apiKey + baseUrl + modelName），由 builder 显式创建
- `ReActAgent` —— 推理与工具调用循环，把模型包装成可执行的 Agent，一次问答一个实例

**三个关键点**：
- `ConcurrentHashMap` —— 线程安全，多请求不会重复创建
- `computeIfAbsent` —— 第一次请求才建实例
- `apiKey` 空则用 `"ollama"` —— Ollama 不校验 key，但 OpenAI 兼容客户端要求非空，用 dummy 值占位

## Step 4：Controller 取 id 调工厂

```java
@PostMapping("/chat")
public Map<String, String> chat(@RequestBody Map<String, String> body) {
    String modelId = body.getOrDefault("model", "remote-deepseek");
    OpenAIChatModel model = factory.getOrCreate(modelId);

    // 模型 → Agent → 消息，Agent 负责推理循环
    try (ReActAgent agent = ReActAgent.builder().name("assistant").model(model).build()) {
        Msg msg = Msg.builder()
                .role(MsgRole.USER)
                .textContent(body.get("message"))
                .build();
        String reply = agent.call(msg).block().getTextContent();
        return Map.of("reply", reply == null ? "" : reply);
    }
}
```

**和迁移前的 Spring AI 写法对比**：
```java
// 迁移前 Spring AI: 直接调模型
String reply = model.call(text);

// 现在 AgentScope: 模型交给 ReActAgent, 消息用 Msg 封装
try (ReActAgent agent = ReActAgent.builder().name("assistant").model(model).build()) {
    Msg msg = Msg.builder().role(MsgRole.USER).textContent(text).build();
    String reply = agent.call(msg).block().getTextContent();
}
```

多一层 Agent，换来的是统一的 `Msg` 消息模型、ReAct 推理循环，以及后续接工具调用和记忆的扩展点。

## 为什么 Ollama 和 DeepSeek 都能用 OpenAIChatModel？

因为 Ollama 提供了 OpenAI 兼容端点 `/v1/chat/completions`，DeepSeek 本身就是 OpenAI API 兼容的。AgentScope 的 OpenAI 扩展只认协议不认后端：

```
OpenAIChatModel(baseUrl="https://api.deepseek.com/v1")
    → POST https://api.deepseek.com/v1/chat/completions

OpenAIChatModel(baseUrl="http://localhost:11434/v1")
    → POST http://localhost:11434/v1/chat/completions
```

同一个类，不同 baseUrl → 打到完全不同的服务。

## 踩坑记录

**坑 1：base-url 要写完整 OpenAI 兼容端点**

AgentScope 的 `OpenAIChatModel` 直接使用 `baseUrl` 去请求 `/chat/completions`，不会自动补 `/v1`。所以：
- ✅ DeepSeek 写 `https://api.deepseek.com/v1`
- ✅ Ollama 写 `http://localhost:11434/v1`
- ❌ 只写根地址会 404

**坑 2：AgentScope 没有自动装配**

它不会像 Spring AI 那样自动创建 `OpenAIChatModel` Bean，`chat.models` 也不会被框架读取。模型必须在 `ChatModelFactory` 里通过 builder 显式创建，好处是多模型切换完全由我们控制。

**坑 3：ReActAgent 要及时关闭，调用要 block**

`ReActAgent` 持有底层资源，用 try-with-resources 包起来；`agent.call(msg)` 返回 `Mono<Msg>`，同步场景记得 `block()` 后再 `getTextContent()` 取文本。
